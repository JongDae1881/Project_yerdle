# 옵시디언 작업 지침

이 지침은 이 프로젝트의 `Obsidian/` 보관함을 정리하거나 수정하는 작업에 적용한다. 사용자의 최신 요청을 우선하며, 다음 기준을 기본 작업 방식으로 사용한다.

## 완성 기준

학습자가 처음부터 읽으며 질문과 답의 흐름을 이해하고, 나중에 필요한 부분을 빠르게 찾아볼 수 있게 정리한다. 작업 범위에 해당하는 노트 내용, 문서 안 목차, 폴더 읽기 순서, 내부 링크, 북마크를 함께 점검한다. 폴더로 목차를 옮길 때는 같은 읽기 순서를 반복하는 북마크도 함께 정리한다. 승인된 범위의 누락이나 형식 불일치는 직접 수정한다. 사용자가 설명이나 확인만 요청하면 그 범위를 따른다.

## 노트 구성

- 한 학습 흐름에 속하는 개념은 **통합 학습 노트** 한 편으로 묶는다. 처음 읽거나 전체를 복습할 때는 이 문서 하나로 흐름이 이어지게 쓴다.
- **개별 참고 노트**는 특정 개념이나 비교 질문을 나중에 제목으로 찾아 독립적으로 읽을 수 있게 쓴다. 사용자가 개념 자체를 질문하거나 답변에서 개념의 역할이나 동작 원리를 독립된 학습 주제로 설명한 경우 개별 참고 노트를 마련한다. 기존에 같은 질문에 답하는 노트가 있으면 예시와 설명을 살려 보강한다.
- 대화를 정리할 때는 제목과 첫 질문부터 후속 질문, 사용자가 다시 확인한 이해, 답변에서 구체적으로 다룬 개념과 비교까지 읽는다. 작업 전에 주요 질문과 개념을 적어 보고 각각 연결할 개별 노트를 정한다. 별도 노트가 필요한 주제는 사용자가 하나씩 지목하기 전에 작업 범위에 포함한다.
- 같은 질문을 이해하는 데 함께 필요한 개념은 한 노트에 묶고, 서로 다른 질문에 답하는 개념은 독립적으로 찾아볼 수 있게 나눈다. 한 실습에 MVC와 프론트 컨트롤러가 함께 나오면 MVC는 역할 분담을, 프론트 컨트롤러는 요청의 접수와 분배를 설명하는 노트로 각각 작성하고 서로 연결한다. 개념 간 비교 자체가 중요한 질문이면 비교 제목으로도 찾아갈 수 있게 한다.
- 통합 노트는 질문에서 다음 질문으로 이어지는 흐름을 담고, 관련 절에서 개별 참고 노트로 연결한다. 개별 노트는 해당 주제의 설명과 예시를 그 자리에서 이해할 수 있게 쓴다. 공통 배경과 실습 전체 흐름은 필요한 만큼 요약하고 관련 노트로 연결한다.
- 기존 노트를 재정리할 때는 별도의 정리본을 먼저 만들고 통합한 내용을 설명한다. 원본 교체나 삭제는 사용자가 요청한 범위에서 진행한다.
- 통합 노트의 제목 바로 아래 `관련 개념` 콜아웃에 문서 안 주요 절로 이동하는 링크를 읽는 순서대로 둔다. 개별 참고 노트에서는 직접 참고할 가치가 있는 관련 노트와 연결 이유를 적는다.
- 대화에서 출발한 노트에는 상단에 원본 대화 링크를 남긴다. 실제 질문과 의문은 원문 표현을 최대한 살려 관련 설명 앞에 인용하고, 처음의 의문이 다음 질문이나 이해로 이어진 과정이 드러나게 배치한다.
- 본문은 무엇이 궁금했는지에서 출발해 필요성, 동작 원리, 실제 예시로 이어지게 쓴다. 소제목에는 나중에 찾을 개념이나 질문을 드러내고, 마지막에 답을 떠올려 볼 `복습 질문`을 둔다.
- 여러 구성 요소의 관계는 `ls` 같은 실제 명령이 처리되는 흐름으로 설명한다. 도움이 될 때 익숙한 환경과 대응시킨다. 예를 들어 Terminal.app과 zsh의 역할을 Windows Terminal과 PowerShell에 대응시킬 수 있다.
- 명령어는 코드 형식으로, 역할이나 방식 비교는 표로 표현한다. 실행 흐름은 Mermaid가 이해에 도움이 될 때 사용한다. 설명은 완결된 문장으로 쓰고 중복과 불필요한 구현 세부사항을 줄인다.
- 원본에서 다룬 범위를 기준으로 정리한다. 꼭 필요한 새 배경은 `추가 설명`으로 표시하고, 기술 정보는 필요에 따라 공식 문서에서 확인해 관련 설명 곁에 출처를 붙인다.

상단 형식의 예시는 다음과 같다.

```markdown
# 맥북 개발환경 학습 노트

> [!info] 관련 개념
> - [[#명령 실행]] — 터미널에서 입력한 명령이 실행되는 과정
> - [[#패키지 설치]] — 같은 프로그램을 설치하는 두 가지 방식

## 명령 실행

터미널에서 `ls`를 입력하면 zsh가 실행 파일을 찾고, macOS가 실행한 `ls`가 현재 디렉터리의 목록을 만든다.

## 패키지 설치

호환되는 Bottle이 있으면 Homebrew는 빌드된 결과물을 받아 설치한다. 소스 빌드를 선택하면 내 Mac에서 결과물을 만든다.

## 복습 질문

- Bottle을 설치할 때 프로그램은 어디에서 빌드됐을까?
```

## 연결 관계와 그래프

- 사용자가 말하는 개념 지도·마인드맵의 기본 의도는 내부 링크로 자동 생성되는 Obsidian 그래프 뷰다. 전체 관계 탐색에는 전체 그래프, 현재 개념 주변 탐색에는 로컬 그래프를 사용한다.
- 내부 링크는 같은 문서의 다른 절로 이동하거나, 독자가 실제로 다른 문서를 참고할 필요가 있을 때 쓴다. 그래프 연결은 이런 참조에서 자연스럽게 생기도록 둔다.
- Canvas는 별도의 수동 배치 지도가 요청될 때 사용한다.
- 사용자가 조정한 그래프 필터, 색상, 배율과 패널 배치를 존중한다. 작업과 관련된 설정만 변경한다.

## 폴더와 읽기 순서

- 왼쪽 파일 탐색기를 기본 학습 목차로 사용한다. 학습 주제 폴더 아래에 단계별 폴더를 두고, 폴더와 파일 이름에 `00 · 시작`, `01 · macOS.md`처럼 두 자리 번호를 붙여 이름순으로 읽을 수 있게 한다. 통합 학습 노트는 시작 폴더의 첫 항목에 둔다.
- 개념의 선행 관계를 기준으로 순서를 정한다. 현재 `Obsidian/맥북 개발환경/`의 읽기 순서는 다음과 같다.

| 폴더 | 폴더 안의 읽기 순서 |
| --- | --- |
| 00 · 시작 | 맥북 개발환경 학습 노트 → 맥북 개발환경 시작 |
| 01 · 명령 실행 | macOS → Terminal.app → 셸과 zsh → PATH |
| 02 · 개발 도구 | Homebrew → Xcode Command Line Tools → Homebrew와 Xcode Command Line Tools |
| 03 · 패키지 설치 | Homebrew Formula → Homebrew Bottle → 소스 빌드 → Homebrew의 패키지 설치 방식 비교 |

## 북마크

- 북마크는 자주 여는 노트의 바로가기가 필요할 때만 사용한다. 예를 들어 `맥북 개발환경 학습 노트` 한 편을 등록할 수 있다. 전체 읽기 순서는 파일 탐색기에서 확인한다.
- 북마크를 수정할 때는 `Obsidian/.obsidian/bookmarks.json`을 먼저 읽고 작업 범위 밖의 사용자 항목을 보존한다. 표시 이름은 간결하게 쓰고 실제 파일 경로를 정확히 연결한다.
- 노트를 이동하거나 이름을 바꿀 때는 문서 목차, 내부 링크, 북마크와 관련 작업 공간 경로를 함께 점검한다.

## 파일 작업과 화면 조작

- 노트와 설정 파일을 직접 읽고 수정하는 방식을 기본으로 한다. 화면 조회와 클릭을 반복하는 방식으로 파일 작업을 대신하지 않는다.
- 사용자가 화면 조작을 명시적으로 요청했을 때만 컴퓨터 사용 도구를 사용한다. 그 밖에는 사용자의 다른 컴퓨터 작업을 방해하지 않도록 파일 기반으로 진행한다.
- 표시 문제가 제기되면 먼저 해당 노트, `bookmarks.json`, `workspace.json`, `app.json` 등 관련 파일에서 원인을 조사한다. 조사 전에 화면 확인이 필수라고 단정하지 않는다.
- 실행 중인 앱이 설정을 다시 저장할 수 있음을 고려한다. 최신 파일을 읽고 필요한 부분만 변경하며, 앱 재시작은 화면 조작 승인 없이 수행하지 않는다.
- 결과를 보고할 때 파일에서 확인한 사실과 실제 앱 화면에서 확인한 사실을 정확히 구분한다. 표시 여부를 확인하지 않았다면 화면에서 확인했다고 주장하지 않는다.
- 필요한 부분만 읽고 출력한다. 반복적인 전체 파일 출력, 스크린샷, 불필요한 검색으로 사용량을 늘리지 않는다.

## 완료 전 검증

- 정리할 때 뽑은 주요 질문과 개념을 실제 노트 파일 및 링크에 대조한다. 후속 질문의 비교 주제나 예시 속 핵심 개념까지 봤는지, 개별 참고 대상으로 잡은 주제를 파일 탐색기와 통합 노트에서 각각 찾을 수 있는지 확인한다.
- 상단 `관련 개념` 콜아웃의 문서 내 제목 링크와 다른 노트 링크가 실제 대상에 연결되는지 확인한다. 통합 노트의 원본 출처, 질문 인용, 복습 질문도 점검한다.
- Markdown 표의 열 개수와 코드 블록 종료를 확인한다. 표 안에서 별칭 링크를 사용할 때는 `[[노트\|표시 이름]]`처럼 파이프를 이스케이프하거나 별칭 없는 링크를 사용한다.
- 깨진 링크 조각, 잘린 문장, 제목 중복이 없는지 확인한다. 현재 보관함은 본문의 제목을 사용하고 `showInlineTitle`을 꺼서 중복을 방지한다.
- 파일 탐색기의 폴더와 파일 번호가 의도한 읽기 순서와 맞는지 확인한다. 북마크를 변경했다면 JSON이 유효하고 바로가기 경로가 존재하며 폴더 목차와 중복되지 않는지 확인한다.
- 마지막 답변에는 변경 결과와 필요한 사용법만 간결하게 안내한다.
