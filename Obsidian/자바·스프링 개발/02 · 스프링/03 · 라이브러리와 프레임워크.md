> Spring과 Spring Boot가 라이브러리라고요? 제가 이해한 바로는 프레임워크랑 라이브러리는 다르고, Spring은 프레임워크, Spring Boot는 Spring의 라이브러리인데, 라이브러리와 프레임워크가 무엇이고 차이가 무엇인가요?

내 코드에서 `ArrayList.add()`를 호출하면 라이브러리의 목록 기능을 쓰는 것이다. `GET /rooms`가 들어올 때는 Spring MVC가 요청 처리 흐름을 관리하며 내가 작성한 `getRooms()`를 호출한다. 프레임워크가 필요한 시점에 개발자 코드를 호출하는 이 흐름을 제어의 역전(IoC)의 예로 볼 수 있다. 호출 방향은 흐름을 이해하는 단서다. 라이브러리도 콜백을 호출할 수 있고 프레임워크도 개발자가 직접 호출할 API를 제공한다. [Spring MVC 요청 매핑](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-requestmapping.html)

## 모듈의 뜻과 역할

**모듈**은 소프트웨어 안에서 관련 코드를 기능별로 묶은 구성 단위다. 관련 기능을 함께 관리할 수 있고, Spring처럼 모듈별로 배포하는 경우 프로젝트에 필요한 기능을 골라 가져올 수 있다. 라이브러리와 프레임워크는 코드가 제공하는 역할을 설명하고, 모듈은 그 코드가 어떻게 나뉘어 있는지를 설명한다. 라이브러리도 프레임워크도 여러 모듈로 구성될 수 있다.

| 개념 | 무엇을 설명하나? | 예시 |
| --- | --- | --- |
| 라이브러리 | 내 코드에서 가져다 쓸 수 있는 기능을 제공한다. | Java 표준 라이브러리는 `ArrayList`로 목록을 다루는 기능을 제공한다. |
| 프레임워크 | 앱의 기본 구조와 실행 흐름을 제공한다. | Spring MVC는 `GET /rooms`를 처리할 컨트롤러 메서드를 찾아 호출한다. |
| 모듈 | 큰 코드베이스 안에서 관련 기능을 묶는 단위다. | Spring Framework의 `spring-webmvc`에는 Spring MVC를 구현하는 코드가 들어 있다. |

Spring Framework는 프레임워크이고, `spring-webmvc`는 그 구성 모듈이다. `spring-webmvc-<버전>.jar`는 그 모듈의 컴파일된 코드 등을 담아 배포하는 파일이다. Maven이나 Gradle이 이 JAR를 의존성으로 가져오면 프로젝트에서 Spring MVC의 기능을 쓸 수 있다. [Spring Framework 개요](https://docs.spring.io/spring-framework/reference/overview.html), [Spring Web MVC](https://docs.spring.io/spring-framework/reference/web/webmvc.html)

Spring Boot는 Spring 기반 애플리케이션을 쉽게 구성하고 실행하도록 자동 설정, 스타터, 빌드 플러그인 등을 제공하는 프로젝트다. 웹 스타터를 의존성으로 선언하면 빌드 도구가 `spring-webmvc` 같은 모듈을 함께 가져온다. [Spring Boot 빌드 도구와 스타터](https://docs.spring.io/spring-boot/reference/using/build-systems.html)
