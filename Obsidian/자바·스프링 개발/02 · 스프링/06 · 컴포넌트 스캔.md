> 기본 Application.java 기본 코드에서 왜 굳이 ComponentScan을 하고, AutoConfiguration을 하는 거죠? 둘 다 패키지 내 다른 곳에서 해도 되는 거 아닌가요?

## Spring은 RoomService를 어떻게 찾을까?

Spring이 `RoomService`를 관리하려면 먼저 컨테이너에 그 객체를 어떻게 만들지 알려 주는 Bean 정의가 있어야 한다. `@Configuration` 클래스에 `@Bean` 메서드를 선언하는 방법이 있고, 컴포넌트 스캔으로 Spring이 대상 클래스를 발견하게 하는 방법도 있다. `@ComponentScan`은 지정한 패키지와 하위 패키지를 탐색해 기본 조건을 만족하는 클래스의 Bean 정의를 등록한다. 등록된 `RoomService`에 생성자 의존성이 있으면 컨테이너가 인스턴스를 만들면서 해결한다. [Spring의 컴포넌트 스캔](https://docs.spring.io/spring-framework/reference/core/beans/classpath-scanning.html)

| 애너테이션 | 코드에 표시하는 역할 |
| --- | --- |
| `@Component` | Spring이 관리할 일반 컴포넌트 |
| `@Service` | 게임방 관리 같은 업무 기능을 담당하는 컴포넌트 |
| `@Repository` | 데이터 저장소에 접근하는 컴포넌트 |
| `@Controller`, `@RestController` | Spring MVC 요청을 처리하는 컴포넌트 |

예를 들어 `com.yerdle.backend.room.RoomService`에 `@Service`를 붙이면 탐색 범위에 들어 있는 경우 Spring이 `RoomService`의 Bean 정의를 등록한다. `RoomService`가 생성자로 받는 `RoomCodeGenerator`를 `@Bean`으로 등록해 두면 같은 컨텍스트에서 두 방식이 함께 동작한다. 명시적 등록 예시는 [[05 · Spring Bean과 자바 설정|Spring Bean과 자바 설정]]에서 볼 수 있다. [Spring의 컴포넌트 역할과 탐색](https://docs.spring.io/spring-framework/reference/core/beans/classpath-scanning.html), [Spring의 Java 기반 설정](https://docs.spring.io/spring-framework/reference/core/beans/java/basic-concepts.html)

## 시작 클래스가 패키지의 위쪽에 있는 이유

`@SpringBootApplication`에 포함된 `@ComponentScan`은 범위를 따로 지정하지 않으면 애너테이션이 붙은 클래스의 패키지부터 탐색한다. 아래 예에서 `YerdleBackendApplication`이 `com.yerdle.backend`에 있으면 `room`과 `user` 하위 패키지를 모두 살핀다. [Spring Boot 패키지 구조](https://docs.spring.io/spring-boot/reference/using/structuring-your-code.html)

```text
com.yerdle.backend
├── YerdleBackendApplication
├── room
│   ├── RoomController
│   └── RoomService
└── user
    └── UserService
```

`YerdleBackendApplication`을 `com.yerdle.backend.room`으로 옮기면 기본 범위가 `room`과 그 하위 패키지로 좁아진다. 이때 형제 패키지 `com.yerdle.backend.user`의 `UserService`를 포함하려면 `@SpringBootApplication(scanBasePackages = "com.yerdle.backend")`처럼 컴포넌트 탐색 범위를 지정할 수 있다. 이 옵션의 범위는 `@ComponentScan`이다. JPA 엔티티와 Spring Data 리포지토리의 탐색 범위는 해당 기술의 설정을 따른다. [SpringBootApplication의 탐색 범위 옵션](https://docs.spring.io/spring-boot/api/java/org/springframework/boot/autoconfigure/SpringBootApplication.html#scanBasePackages())

## 다른 설정 클래스에서 스캔하기

`@Configuration`이 붙은 `RoomScanConfig`에 `@ComponentScan("com.yerdle.backend.room")`을 선언해도 된다. 그 설정 클래스를 앱의 시작 설정에 `@Import(RoomScanConfig.class)`로 연결하면 Spring이 설정을 읽고 스캔을 실행한다. 기존 `@SpringBootApplication`의 기본 스캔을 유지하면 그 범위도 적용된다. 탐색 범위를 별도 설정에서만 정하고 싶다면 시작 설정에서 `@SpringBootConfiguration`, `@EnableAutoConfiguration`, `@Import`를 조합할 수 있다. [Spring의 설정 가져오기](https://docs.spring.io/spring-framework/reference/core/beans/java/composing-configuration-classes.html), [SpringBootApplication 구성 선택](https://docs.spring.io/spring-boot/reference/using/using-the-springbootapplication-annotation.html)

| 궁금한 것 | 동작을 담당하는 기능 |
| --- | --- |
| 내가 만든 `RoomService`를 어디서 찾아 등록할까? | 지정한 패키지를 살피는 컴포넌트 스캔 |
| 어떤 웹 서버와 MVC 기본 구성을 적용할까? | 클래스패스와 설정 조건을 평가하는 [[07 · Spring Boot 자동 설정\|Spring Boot 자동 설정]] |

## 복습 질문

- `@Service`가 붙은 클래스를 탐색했을 때 Spring은 무엇을 등록할까? 실제 객체 생성과 주입은 누가 맡을까?
- 시작 클래스를 `room` 패키지로 옮겼을 때 `user.UserService`까지 탐색하려면 무엇을 바꿀 수 있을까?
- 다른 패키지의 설정 클래스에 `@ComponentScan`을 붙였다면 그 설정을 어떻게 시작 설정에 연결할까?
