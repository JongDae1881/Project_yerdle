## 함께 동작하기 위해 무엇을 약속할까?

서블릿 기반 Java 웹 앱에서는 연결을 받고 HTTP 메시지를 읽고 전송하는 공통 작업을 컨테이너가 맡는다. 애플리케이션은 Jakarta Servlet API의 타입을 사용해 파라미터를 읽거나 응답을 작성하며 필요한 기능을 구현한다.

| 구성 요소 | 역할 | 실습에서 볼 수 있는 예 |
| --- | --- | --- |
| Jakarta Servlet 규격과 API | 서블릿과 실행 환경이 함께 지킬 계약을 정한다. 생명주기 메서드와 요청·응답 타입을 정의한다. | `Servlet`, `HttpServlet`, `HttpServletRequest`, `HttpServletResponse` |
| 서블릿 컨테이너 | 규격에 따라 웹 앱을 로딩하고 매핑을 구성한다. 서블릿 인스턴스를 생성·초기화하고 요청이 들어오면 호출한다. | Tomcat의 서블릿 실행 기능 |
| 서블릿 | 규격에 맞춰 애플리케이션의 요청 처리를 컨테이너에 연결하는 객체다. | 실습의 `MainServlet`, Spring MVC의 `DispatcherServlet` |

`3logindao`의 `jakarta.servlet-api`는 컴파일할 때 쓸 표준 타입을 제공한다. 실제 HTTP 요청을 받으려면 실행 환경이 필요하다. 외장 방식에서는 Eclipse의 **Run on Server** 등으로 지정한 Tomcat에 웹 앱을 배포한다. Servlet API를 지원하는 호환 컨테이너도 그 규격에 맞는 서블릿을 실행할 수 있다. [Jakarta Servlet 명세](https://jakarta.ee/specifications/servlet/6.1/jakarta-servlet-spec-6.1.html), [Tomcat이 구현하는 명세](https://tomcat.apache.org/whichversion.html)

## 요청이 들어오면 누가 메서드를 호출할까?

컨테이너는 웹 앱에 선언된 `@WebServlet`이나 `web.xml`의 URL 매핑을 사용한다. `@WebServlet("/main")`은 해당 앱의 `/main` 요청에 연결할 서블릿을 지정한다. 예를 들어 `GET /logindao/main?action=list`에서 `/logindao`는 앱을 고르는 컨텍스트 경로이고, `/main`은 Tomcat이 `MainServlet`을 고르는 경로다. `action=list`는 선택된 서블릿이 읽는 요청 파라미터다. [Jakarta Servlet 명세 §8과 §12](https://jakarta.ee/specifications/servlet/6.1/jakarta-servlet-spec-6.1.html)

| 서블릿 생명주기 | 컨테이너가 하는 일 |
| --- | --- |
| 생성과 `init()` | 설정에 따라 배포 시점이나 요청에 처음 필요할 때 인스턴스를 만들고, 첫 요청 처리 전에 초기화한다. |
| `service()` | 요청·응답 객체를 넘겨 호출한다. `HttpServlet`을 상속한 경우 `service()`가 HTTP 메서드에 따라 GET은 `doGet()`, POST는 `doPost()` 등으로 보낸다. |
| `destroy()` | 앱을 내리거나 서블릿을 서비스에서 제거할 때 정리 작업을 할 수 있도록 호출한다. |

서블릿은 `HttpServletRequest`에서 파라미터나 헤더를 읽고 `HttpServletResponse`를 사용해 응답 상태, 헤더, 본문 등을 작성한다. 일반적인 단일 컨테이너에서는 등록된 서블릿 하나의 인스턴스가 여러 요청에 재사용된다. 여러 요청이 동시에 오면 같은 인스턴스가 서로 다른 스레드에서 호출될 수 있으므로, 현재 사용자의 값은 지역 변수나 해당 요청의 속성에 둔다. 개발자가 메서드를 작성하고 컨테이너가 호출 시점을 정한다는 점에서 [[04 · IoC·DI와 Spring 컨테이너|IoC]]와도 연결된다. [Jakarta Servlet 생명주기와 동시 요청 처리](https://jakarta.ee/specifications/servlet/6.1/jakarta-servlet-spec-6.1.html#servlet-life-cycle)

## Spring MVC에서도 서블릿을 쓰는가?

서블릿 기반 Spring MVC에서는 프레임워크가 제공하는 `DispatcherServlet`이 HTTP 요청의 진입점이 된다. Tomcat이 이 서블릿을 호출하면 Spring MVC가 요청에 맞는 컨트롤러 메서드를 호출한다. 개발자는 보통 `@GetMapping` 등을 사용하는 컨트롤러를 작성한다. 요청이 어느 층에서 처리되는지 확인할 때는 **Tomcat이 선택한 서블릿**과 **Spring MVC가 선택한 컨트롤러 메서드**를 구분하면 된다. [Spring MVC의 DispatcherServlet](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-servlet.html)
